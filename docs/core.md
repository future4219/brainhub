## 核

Project Brain は **領域ごとの脳を、利用者が普段使う AI クライアントへ MCP で直接挿せるようにする場**である。

比喩としては「知識の GitHub」。リポジトリの代わりに脳が置かれ、public なら誰でも、private なら招待された者だけが接続できる。

## 核を構成する4条件

1. 脳の中身は人間が読める Markdown + git である。持ち出せる。
2. 脳は領域ごとに分かれる。ひとつの脳へ全領域を入れない。
3. 脳は組み合わせられる。複数の脳を同時に読ませ、ひとつの窓から引ける（federated-read）。
4. 読む側は Claude / ChatGPT / Codex / Claude Code である。ブラウザではない。

## 読む場所についての判断

チャット UI は既に世界に十分ある。不足しているのは中身の側である。

したがって Project Brain は**チャット体験を提供しない**。利用者は自分が既に使っている AI クライアントから接続する。

この判断は、リモート MCP コネクタの接続手順が「URL を貼って Add を押す」だけであり、ローカル MCP のような設定ファイル編集を伴わないという事実に依拠する。非エンジニアが MCP を設定できないという前提は、ローカル MCP に限って正しい。

## Web アプリの役割

チャットではなく、管理面と店先である。

- 脳を立てる
- 招待する / 公開する
- 知識を書く・直す
- **接続前に人間が中身を読む公開ページ**（GitHub のリポジトリページに相当）

public な脳を出す以上、繋ぐ前に「何が入っていて、誰が作り、繋ぐと何ができるか」を人間が読める場所が要る。これは Web アプリでしか担えない唯一の役割である。

## 非目標

以下は明示的に作らない。

- ChatGPT の劣化版となるチャット機能
- 会話ログの蓄積とその検索
- 全領域を収めた単一の巨大な脳

## テナント分離の方針

脳の分離には二段階がある。

- **source 分離**: ひとつの GBrain 内で領域ごとに source を分ける。git リポジトリも分かれる。組み合わせは `--federated-read` で行う。
- **runtime 分離**: 脳ごとに DB / MCP ランタイム / 認証基盤を分ける。`brain_runtimes` の `cluster_ref` `database_ref` が担う。

**当面はすべての脳を source 分離で運用する。** `brains` / `memberships` / `brain_runtimes` は保持し、全 brain が同一の `cluster_ref` `database_ref` を指す状態から始める。

他者がテナントとして脳を持つ段階で、当該 brain の参照値のみを差し替えて runtime 分離へ移す。テーブルは既に存在するため追加実装を要しない。

組み合わせ（条件3）は source 分離でのみ安価に成立する。runtime を跨ぐと横断検索のマージとランキングを自前で書くことになるため、分離を強めるほど組み合わせが難しくなる。必要のない分離は行わない。

## 適用範囲外として削除する実装

核に照らして、以下は核へ寄与しない。

| 対象 | 判断 | 根拠 |
|---|---|---|
| export / delete / restore（data-jobs, exports） | 削除 | 起動する UI も API も存在しない。download 経路のみが実装されている |
| conversation projection（conversation, worker） | 削除 | `--no-federated` のため外部クライアントからは構造的に不可視。Web チャット専用経路である |
| Web チャットと会話原文保存（chat, sessions, brain-app） | 公開ページ成立後に削除 | 読む場所についての判断より、核の外側 |
| brains / memberships / brain_runtimes | **保持** | テナント分離の方針の土台 |

削除対象は git 履歴に残る。将来必要になった際は、その時点の要件で再実装する方が、入口のない実装を維持するより安い。

## 未確定事項

1. https 公開と authorization_code 対応。未着手。これが動くまで製品は成立しない。
2. public 脳を認証なしコネクタで成立させられるか。上流 GBrain の serve 実装で要確認。
3. 他者が脳を立てる導線。未着手。
4. 二番目の領域。**現時点では決めない。** 一番目の脳を公開し、接続者から立ち上がるのが正しい順序である。

## 良い public 脳の条件

LLM が素で答えられないことのみが価値を持つ。

- 訓練データに含まれないほど新しい
- 公開されていない実務知
- 散在していて集めるのが困難
- 変化が速く訓練データが常に古い

一般論としての会計・法務・税務はこの条件を満たさない。狭く新しい部分のみが該当する。領域を大きく取らない。
