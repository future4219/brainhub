# brainhub デザイン指針

AI に UI を書かせるときは、このファイルを一緒に読ませる。`docs/architecture-guide.md` がコードの指針であるのと同じ役割を、見た目に対して持つ。

## 立ち位置

小さなスタジオのデザインリードとして扱う。テンプレートに見える案は却下されている。**このプロダクト固有の判断**を求める。

制約の列挙だけを渡さないこと。「認証なし」「React Router を使わない」は制約であって方向ではない。方向がなければ既定のスキャフォールドが出てくる。

## 何を作っているか

**知識のリポジトリを置く場所。** 読みに来るのは人間ではなく AI である。

人間がこのページに来る目的はひとつだけ。

> **繋ぐ価値があるか判断する。**

購入でも登録でもない。中身を見て、良さそうなら URL をコピーして自分の AI に貼る。ページの仕事はそこで終わる。

対象読者はエンジニアと、AI クライアントを日常的に使う人。専門用語を避ける必要はない。むしろ噛み砕きすぎると信用されない。

## 題材から引く

デザインの語彙は、このプロダクトの世界から取る。ゼネリックな SaaS の語彙を持ち込まない。

この世界にあるもの:

- **Markdown と git** — プレーンテキスト、コミット履歴、diff、モノスペース
- **リポジトリ** — 一覧、ファイルツリー、更新日時、コミット数
- **引用** — slug は不変の引用キー。学術的な参照に近い
- **type の分類** — decision / idea / research / note / concept — これは装飾ではなく実際の構造
- **接続** — エンドポイント、トークン、ハンドシェイク

この世界に**無いもの**（持ち込まない）:

- ヒーロー画像、抽象的な 3D レンダー、グラデーションのメッシュ
- 「AI で生産性を10倍に」的なマーケティングコピー
- 顔写真つきの証言、ロゴの帯、価格表
- 曖昧なイラスト（ノートパソコンを見る人物、浮かぶカード）

## 参照すべきもの / しないもの

**近い**: GitHub のリポジトリページ、Read the Docs、arXiv の abstract ページ、npm のパッケージページ、辞書や索引の組版

**遠い**: Vercel / Linear 系のダークグラデーション、Stripe 風のマーケティング LP、汎用ダッシュボードテンプレート

## 避けるべき既定値

現在の AI 生成デザインは3つの見た目に収束している。どれもこの題材のために選ばれたものではないため、使わない。

1. クリーム色の背景（#F4F1EA 近辺）＋ 高コントラストのセリフ見出し ＋ テラコッタのアクセント（#D97757 近辺）
2. ほぼ黒の背景 ＋ 蛍光グリーンかバーミリオンのアクセント1色
3. 新聞風のヘアライン罫 ＋ border-radius ゼロ ＋ 密なカラム

3 は題材に近いので誘惑がある。**採用するなら「なぜこの題材に合うか」を1文で説明できること。**説明できないなら別の方向を取る。

## 進め方

コードを書く前に、必ず設計を先に出す。

**第1パス — トークンを決める**

- **色**: 4〜6個の名前つき hex。役割を明記する
- **書体**: 2〜3の役割（見出し / 本文 / データ・コード）。同じファミリで済ませない
- **レイアウト**: 一文の説明と ASCII のワイヤーフレームで2案以上を比較する
- **signature**: このページが記憶される唯一の要素。1つだけ

**第2パス — 自己批判**

出した案を、上の「避けるべき既定値」と照らす。似た依頼で同じものを出しそうな箇所があれば、**何を変えたかと理由を述べてから**直す。

そのうえでコードを書く。**トークンから外れた色や書体を後から足さない。**

## 判断の基準

**大胆さは1箇所に使う。** signature 要素だけを記憶に残るものにして、周囲は静かに保つ。

**構造は情報である。** 番号・見出し・罫線は、内容として真であるものだけを表す。`01 / 02 / 03` は実際に順序があるときだけ使う。ページ一覧に順序はない。

**type の分類は本物の構造である。** decision / idea / research は色分けの口実ではなく、この脳が何でできているかを示す。フィルタが装飾ではなく実際の道具として機能すること。

**動きは控えめに。** 過剰なアニメーションは AI 生成らしさの主要因になる。入れるなら1箇所、理由を言えるものだけ。

**密度を恐れない。** 139件のページ一覧が主役である。カードを大きくして余白で薄めると、中身の量という一番の説得材料が消える。

## 文言

- 能動態。ボタンは起きることをそのまま書く。「送信」ではなく「コピー」
- システムの都合ではなく、利用者が認識する名前で呼ぶ
- 空の状態は行動への誘い。エラーは何が起きて次に何をするかを述べる。謝らない
- 各要素はひとつの仕事だけをする。ラベルはラベル、例は例

## 品質の床

宣言せずに満たす。

- モバイルまでレスポンシブ
- キーボードフォーカスが見える
- `prefers-reduced-motion` を尊重
- ダークモードで全テキストが読める

## この段階でのページ

**トップ** — 置かれている脳の一覧。GitHub のプロフィールページに相当。

**脳の詳細** — その脳のページ一覧、type でのフィルタ、MCP URL。GitHub のリポジトリページに相当。

主役は139件のページ一覧である。「AI に知識を繋ぐ」という説明文ではない。**中身を見せることが説得であり、説明は補助にすぎない。**
